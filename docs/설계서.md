# 대성중학교 수업 도구 나눔터 설계서

> 대성중학교 선생님들이 바이브 코딩으로 직접 만든 교육용 프로그램을 올리고, 모두가 수업에서 꺼내 쓰는 사이트.
> 이 문서는 사이트의 큰 틀입니다. 기능을 추가하거나 고칠 때 먼저 이 문서와 맞는지 확인합니다.

- 작성일: 2026-11-11
- 상태: 1단계 완료(화면 틀과 체험용 동작), 2단계 진행 중(서버용 코드 완료, 실제 서버 연결 전)

## 0. 낱말

- **도구**: 선생님이 바이브 코딩으로 직접 만든 **웹앱 프로그램**. 사이트가 미리 넣어 두는 타이머·발표자 뽑기 같은 기능이 아닙니다. 이 사이트는 도구를 만들지 않고, 선생님들이 만든 도구를 모으고 나누는 자리입니다.
- **제작자**: 도구를 만들어 올린 선생님.

## 1. 목표

1. **수업 중에 쉽게 접근한다.** 교실 컴퓨터에서 주소 하나로 들어와 두 번 안에 도구가 뜬다.
2. **과목별로 쉽게 찾는다.** 과목으로 나뉘어 있고, 검색과 즐겨찾기로 필요한 도구를 바로 꺼낸다.
3. **쉽게 올려 공유한다.** 만든 파일을 끌어다 놓고 몇 칸만 채우면 끝난다.
4. **만든 이야기가 보인다.** 모든 도구에 누가, 언제, 어떤 의도로 만들었는지 남는다.
5. **서로 북돋고 다듬는다.** '좋아요'로 응원하고, '고쳤으면 하는 점'을 제작자에게 전한다.

## 2. 사용 장면

| 장면 | 사용자 | 필요한 것 |
|---|---|---|
| 수업 직전·수업 중 | 도구를 쓰는 선생님 | 과목 선택 → 카드의 '열기' → 전체 화면 |
| 수업 준비 | 도구를 고르는 선생님 | 만든 의도·사용 방법을 읽고 즐겨찾기에 담기 |
| 도구를 만든 뒤 | 도구를 올리는 선생님 | HTML 파일 끌어다 놓기 또는 링크 붙여넣기 |
| 써 본 뒤 | 의견을 주는 선생님 | 좋아요, 고쳤으면 하는 점 보내기 |
| 의견을 받은 뒤 | 제작자 | '내 도구'에서 받은 의견 확인 → 고쳐서 다시 올리기 |

## 3. 설계 원칙

- **찾기가 먼저다.** 첫 화면이 곧 도구 목록이다. 소개 문구나 공지보다 검색·과목·카드가 위에 온다.
- **열기는 한 번에.** 카드마다 '열기' 버튼이 있어 상세 화면을 거치지 않고 바로 실행한다.
- **올리기는 다섯 칸.** 필수 입력은 제목, 한 줄 소개, 과목, 만든 의도, 파일(또는 링크)뿐이다.
- **교실 화면 기준.** 큰 글씨, 넉넉한 버튼, 전자칠판·빔프로젝터에서 읽히는 대비.
- **차분하고 단정하게, 항상 밝게.** 컴퓨터가 어두운 모드여도 밝은 화면으로 보인다(빔프로젝터·전자칠판 기준).
- **색은 네 가지.** 짙은 청색 `#355872`(버튼·제목), 중간 파랑 `#7AAACE`(테두리 강조), 하늘색 `#9CD5FF`(선택 표시), 크림색 `#F7F8F0`(바탕). `css/styles.css` 맨 위 네 줄만 바꾸면 사이트 전체 색이 바뀐다. 과목별 색은 꼬리표와 기본 그림에만 옅게 쓴다.
- **도구마다 얼굴이 있다.** 썸네일을 넣을 수 있고, 넣지 않으면 과목 색의 귀여운 캐릭터 그림이 자동으로 들어간다(도구마다 생김새가 조금씩 다름).

## 6. 올리는 방식

바이브 코딩 결과물은 대부분 둘 중 하나이므로 두 가지만 받습니다.

1. **HTML 파일 한 개** — Claude 등에게 "하나의 HTML 파일로 만들어 줘"라고 해서 받은 파일. 사이트 안에서 바로 실행됩니다. 크기 제한 900KB.
2. **링크** — 이미 다른 곳(Claude 아티팩트, 구글 사이트 등)에 올라가 있는 도구의 주소. 새 탭으로 열립니다.

여러 파일로 된 프로그램, 설치형 프로그램은 받지 않습니다(링크로 등록).

## 7. 좋아요와 의견

- **좋아요**: 한 사람이 도구마다 한 번. 다시 누르면 취소. 목록을 좋아요 순으로 정렬할 수 있습니다.
- **고쳤으면 하는 점**: 상세 화면에서 적어 보내면 제작자의 '내 도구'에만 보입니다. 공개 댓글이 아니라 제작자에게 가는 쪽지라서 부담 없이 적을 수 있게 합니다. 보낸 사람 이름은 제작자에게 보입니다.

## 8. 로그인과 권한 (2026-11-11 결정)

- **보기·실행은 누구나.** 주소만 알면 로그인 없이 도구를 찾고 엽니다. 수업 중 접근이 가장 중요하기 때문입니다.
- **올리기·의견·신고는 로그인.** 로그인은 **성함 + 개인 비밀번호**입니다.
- **성함은 관리자가 한 번에 등록합니다.** 관리자 화면(`#/admin`)에 명단을 붙여 넣으면, 그 명단에 있는 성함만 로그인됩니다. 동명이인은 "김민수(수학)"처럼 구분해 등록합니다.
- **첫 로그인 때 개인 비밀번호를 정합니다.** 성함을 넣고, 학교에서 안내한 **가입 코드(학교 공용)** 를 넣은 뒤 내 비밀번호(6자 이상)를 정합니다. 다음부터는 성함과 내 비밀번호만 씁니다. 가입 코드는 아직 로그인하지 않은 성함을 남이 먼저 차지하지 못하게 막는 용도입니다.
- **비밀번호를 잊으면 관리자가 초기화합니다.** 초기화된 선생님은 가입 코드로 다시 정합니다.
- **올린 도구는 바로 공개됩니다.** 문제가 있으면 누구든 '문제 신고'를 하고, 관리자가 확인해 내립니다.

알고 쓰는 것:

- 가입 코드가 새어 나가면, **아직 한 번도 로그인하지 않은 선생님**의 성함을 남이 차지할 수 있습니다. 명단 등록 직후 모든 선생님이 한 번씩 로그인해 두고, 가입 코드는 학기마다 바꾸는 것을 권합니다.
- 비밀번호 확인과 보관은 반드시 **서버에서** 해야 합니다. 체험용(`js/store.js`)은 가입 코드와 관리자 비밀번호가 파일 안에 그대로 있고, 개인 비밀번호도 그 브라우저에만 저장됩니다. **서버에 연결하지 않은 채로 배포하면 안 됩니다.** 서버용에서는 가입 코드·관리자 비밀번호를 관리자가 Supabase에서 직접 정하고(어떤 파일에도 적지 않음), 모두 변환해 저장합니다.
- 비밀번호를 다섯 번 틀리면 5분 동안 잠깁니다. 남이 일부러 틀려서 그 선생님을 5분씩 못 들어오게 할 수는 있습니다.

## 8-1. 기술 구조

```
[선생님 브라우저]
   │  정적 사이트 (HTML·CSS·JS, 빌드 과정 없음)
   ▼
[무료 호스팅]  사이트 본체
   │
   ▼
[서버(무료 서비스)]  ① 성함·비밀번호 확인  ② 도구·좋아요·의견·신고·명단 저장

[별도 주소]  올라온 도구(HTML)를 내보내는 곳 — 사이트 본체와 분리
```

- **빌드 도구를 쓰지 않습니다.** 파일을 그대로 올리면 동작해서 선생님 누구나 이어받아 관리할 수 있습니다.
- **저장 계층을 한 파일로 분리했습니다.** 화면 코드(`js/app.js`)는 `js/store.js`의 함수만 부릅니다. 지금 `store.js`는 브라우저 저장소(localStorage)를 쓰는 체험용이고, 2단계에서 이 파일만 서버용으로 바꿉니다. 이를 위해 `getUser()`를 뺀 모든 함수가 이미 Promise를 돌려주고 `app.js`도 기다렸다가(await) 받도록 되어 있어서(2026-11-11), 함수 이름·인자·돌려주는 값만 지키면 `app.js`는 손대지 않아도 됩니다.
- **서버는 Supabase입니다(2026-11-11 결정).** 구글 로그인을 쓰지 않으므로 비밀번호를 서버 쪽에서 확인해야 하는데, Supabase는 무료 요금제에서 데이터베이스 함수로 할 수 있습니다. 표는 모두 잠그고 사이트는 `supabase/setup.sql`의 함수만 부릅니다. 설치 순서는 `docs/서버-설치.md`.
- **`js/config.js`가 비어 있으면 체험용, 채우면 서버용.** 서버용 저장 계층은 `js/store-supabase.js`이고, 체험용과 함수 이름·돌려주는 값이 같습니다.
- 무료 요금제는 일주일쯤 사용이 없으면 프로젝트가 멈춥니다. 방학 뒤에는 관리자가 대시보드에서 다시 켭니다.
- **올라온 도구는 별도 주소에서 내보냅니다.** 점수·진행 상황을 기억하는 웹앱을 살리기로 했기 때문입니다. 사이트 본체와 주소(도메인)가 다르면, 웹앱이 자기 저장소는 쓰되 사이트의 로그인 정보에는 닿지 못합니다. 초안은 아직 격리 실행(저장 불가) 상태입니다.
- HTML 파일 크기 제한 900KB는 서버 저장 한도를 고려한 임시 값이며 서버를 고른 뒤 다시 정합니다.

### 서버에 저장하는 자료

```
teachers   등록된 성함과 변환된 비밀번호 (관리자만 수정)
tools      도구 정보 + html 본문 또는 url
likes      도구별 좋아요 (브라우저마다 한 번)
feedback   의견 (제작자만 읽기)
reports    신고 (관리자만 읽기)
sessions   로그인 표 (선생님 180일, 관리자 12시간)

```

즐겨찾기는 교실 컴퓨터마다 따로 두는 것이라 서버에 올리지 않고 그 브라우저에만 둡니다.

## 9. 안전과 개인정보

- **올린 HTML은 사이트와 떼어 놓고 실행합니다.** 올라온 프로그램이 사이트의 로그인 정보나 다른 도구의 데이터에 손대지 못하게 합니다. 초안은 iframe `sandbox`로 격리하고, 2단계에서 별도 주소 방식으로 바꿉니다(8-1절).
- **초안의 부작용**: 격리 실행 중에는 올라온 웹앱이 브라우저 저장소(localStorage)를 쓸 수 없어, 점수나 진행 상황을 기억하는 기능이 동작하지 않습니다.
- **좋아요**는 로그인 없이 브라우저마다 한 번으로 셉니다. 수업 중 로그인 없이 쓰는 흐름을 살리기 위해서이며, 마음먹으면 수를 부풀릴 수 있습니다. (서버용도 일단 이 방식으로 만들었고, 로그인한 사람만 누르게 바꿀지는 아직 열려 있습니다.)
- **학생 개인정보를 올리지 않습니다.** 도구 파일 안에 학생 이름·성적 등을 넣어 올리지 않도록 올리기 화면에 안내합니다. 이름을 입력해 쓰는 도구는 그 내용이 교실 컴퓨터 브라우저에만 남도록 만듭니다.
- **관리자**는 신고된 도구를 확인하고 내릴 수 있습니다(`#/admin`).

## 10. 단계

| 단계 | 내용 | 상태 |
